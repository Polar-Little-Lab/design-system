# 개발 규칙

1. docs/AI_HANDOFF.md와 COMPONENTS.md를 먼저 읽습니다.
2. 기존 컴포넌트와 토큰으로 화면을 구성합니다. 앱별 버튼·선택 메뉴 CSS를 복제하지 않습니다.
3. 새로운 상태나 컴포넌트가 필요하면 Storybook에 정상·오류·비활성·키보드 예제를 먼저 추가합니다.
4. 의미 있는 상호작용 테스트와 해당 소비 앱 검증을 수행합니다.
5. 구현 범위와 변경 이력·AI 전달 문서를 함께 갱신합니다.

## 구조

- tokens/ → scripts/tokens.mjs → src/tokens.css + Qt 토큰 사본
- src/components/ → 제품 독립적인 React 컨트롤
- src/stories/ → 문서·상태·검증 패턴
- adapters/qt/ → 별도 Python 패키지
- docs/ → 프레임워크를 넘어 공유하는 명세

디자인 시스템이 소비 앱의 SSH·압축·키체인 코드를 import하지 않도록 합니다.
브랜드·제품 레이아웃과 업무 로직은 소비 앱에 둡니다.
웹과 Qt의 렌더링 코드를 억지로 공유하지 않습니다. 의미·동작 계약을 공유합니다.

## 검증

npm run build → npm test. 키보드·마우스·포커스·스크롤·반응형을 확인합니다.
Accessibility 패널과 axe 자동 검사는 수동 스크린 리더 검증을 대체하지 않습니다.
새 어댑터를 만들 때 이미 다른 플랫폼에서 검증됐다고 가정하지 않습니다.

## 변경

API 의미를 바꾸면 major, 호환 기능 추가는 minor, 수정은 patch.
현재 0.1.0은 초기 버전입니다. 소비 앱의 적용 버전을 기록합니다.
배포 태그는 고정하고, 변경 시 새 버전을 만듭니다.
npm 게시·저장소 공개 전환·공개 호스팅은 별도의 명시적 요청이 있을 때 수행합니다.
