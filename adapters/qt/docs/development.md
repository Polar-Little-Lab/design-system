# 공통 컴포넌트 개발 규칙

## 기본 순서

1. 새 화면보다 먼저 필요한 컴포넌트와 상태를 나열합니다.
2. Polar UI의 기존 컴포넌트를 우선 사용합니다.
3. 없는 상태는 제품 화면의 로컬 스타일로 땜질하지 않고 패키지의 API·갤러리에 추가합니다.
4. 키보드 조작, 비활성, 긴 문구, 오류와 최소 창 크기를 검사합니다.
5. 컴포넌트 테스트 후 소비 앱의 테스트·패키징을 검증합니다.
6. API 또는 기본 동작을 변경하면 계약 문서와 변경 이력을 함께 수정합니다.

## 소유권과 의존성

제품 → Polar UI → Qt 방향만 허용합니다. Polar UI는 앱의 압축·SSH·키체인 모듈을 import하지 않습니다.
상태 변경과 값 전달만 컴포넌트가 담당합니다. 저장·삭제·암호 검증·네트워크 요청은 제품 코드가 담당합니다.
‘삭제’ 버튼 자체가 데이터를 삭제하거나 별도의 확인 정책을 강제하지 않습니다.

브랜드 로고는 각 제품에 둡니다. 공통 UI 아이콘은 24 그리드, 1.8px 획을 기준으로 하며 글자 화살표·이모지로 대체하지 않습니다.
아이콘만 있는 버튼에는 의미를 설명하는 접근성 이름과 툴팁이 필요합니다. 설명을 툴팁에만 넣지 않습니다.

## 레이아웃과 상태

- 40px 컨트롤 기준. 영구 라벨과 입력 사이 8px, 필드 간 12px 이상.
- 포커스 테두리가 생겨도 컨트롤 크기와 글자 위치가 움직이지 않아야 합니다.
- 선택값과 키보드로 이동 중인 항목을 구분합니다. Escape는 값을 바꾸지 않고 닫습니다.
- 설정 화면의 스크롤이 선택값을 바꾸면 안 됩니다.
- placeholder는 라벨을 대체하지 않습니다. 오류는 해당 필드 아래에 표시합니다.
- 작업 중에는 실행 버튼을 비활성화하고 진행 상태를 표시합니다. 취소 버튼까지 함께 막지 않습니다.
- 암호는 컴포넌트가 저장하지 않습니다. 값의 수명과 삭제는 제품이 관리합니다.

## 토큰과 플랫폼

토큰 변경은 tokens.json에서 시작합니다. CSS 변수는 export_tokens.py로 재생성합니다.
플랫폼별 렌더링·접근성 코드는 공유하려고 억지로 합치지 않습니다.
React 어댑터는 같은 의미 토큰과 컴포넌트 계약을 따르되 ARIA·브라우저 포커스 관리를 별도로 구현해야 합니다.
플랫폼 하나에서 통과한 것을 다른 플랫폼의 검증 완료로 기록하지 않습니다.

## 변경·배포

- 호환되는 추가 API: minor, 버그 수정: patch, 기존 API 의미 변경: major.
- 소비 앱은 패키지 버전을 고정하고 변경 이력을 확인합니다.
- PyInstaller에는 polar_ui의 JSON·SVG 리소스를 collect_data_files로 포함합니다.
- 갤러리 렌더는 실제 위젯의 테스트 데이터 화면이며 사용자 앱의 네이티브 캡처로 표시하지 않습니다.
